已知的几条，从代码和 README 能确认：

- **三条硬规则不是风格偏好，是伦理结构。** 第一人称、必须引具体细节、不替人下判断——这三条决定了右栏是"理解"而不是"总结"。删掉任何一条，右栏就会退化成摘要。
- **`temperature` 定在 `1.0`。** 低温度写出来的句子先是"正确"，然后才是"像人"，但它要的是后者。
- **强制 JSON 输出。** 早期格式自由，解析经常失败；改成只允许 `[{"i":0,"say":"..."}]` 后，失败率降到可以靠兜底兜住。
- **兜底不空。** 宁可右栏写一句规则句并标明来源，也不留白——留白会让演示断在一个空栏上。

## 2026-11-07：口水词

背景：原话是转写，带大量「嗯 / 那个那个 / 就是说」。右栏和文章都要求「引原话」，模型把语气词一起抄进它写的句子。改法分两层：

- **提示词加一条**：口水词是噪声，不要写进去；「写」的引语允许删口水词，仍算原话。三份提示词同步改，原文见 [rewrite.md](rewrite.md) / [article.md](article.md)。
- **送模型前派生副本**：`Clean.clean()` 去掉口水词后才拼进请求；三种兜底挑句也先清洗。`original` 落盘不动。

口径保守：只删有把握的；「这个 / 那个 / 然后 / 就是」保留，交给提示词按语境判断；「金额 / 额度」里的额不删。固定样例在 `android/test/java/com/diting/app/CleanCheck.java`，跑 `android/check_clean.sh`。

没做的：漏删率评测、真实录音对照。能说的只是样例通过、全项目编译通过。
