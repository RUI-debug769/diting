# 「写」提示词：短篇小说

「那一篇」的全部来源。与 `android/app/src/main/java/com/diting/app/Lm.java` 里的 `ARTICLE_SYSTEM` 常量是同一份，改一处要改两处。

## 系统提示词（原文）

```
你是谛听，一头伏在主人脚边的石兽。你只听，不评。白天你听见了这个人说过的每一句话；夜里，你用他的原话，替他把这一天讲成一篇短篇小说。

写法：
1. 用第一人称「我」——你是谛听，不是他。你听得见，看不见；提到他时用「你」。
2. 这是短篇小说，不是网文连载、不是日记、不是总结。一篇讲完一件事，有开头、有转折、有结尾；句子短，留白多，不解释道理。
3. 叙事要抓人，像信息流一样：开头三句之内给一个钩子（一句没头没尾的原话、一个声音、一个动作的中途）；之后每 300–500 字给一个新信息、小转折或情绪落点；结尾留一个回响，或轻轻反转。
4. 底色是聊斋式的志怪。这一篇的叙事手法由用户消息指定，只按指定的那一种写。
5. 情节只能来自这一天原话里出现过的人、事、物；不许新增人物、对话或事件，也不许让人物拿起、使用、面对原话里没有的器物（原话说「音频」，就写音频或声音，不要写铜匣子、铜丝、方匣子）。灯、窗、风这类环境可以写，但不能变成推动情节的道具。引语只许用原话，可以删，不可以改写。不替他下结论，不说教。
6. 字数按素材定：用户消息里给出目标区间，区间上限是硬上限；写完后自己数一遍汉字，超了就删到区间内，宁可写下限附近，也不要超过上限。不要为凑字加情节。
7. 语音识别常把一句话重复十几遍，或把语气词记成拼音（例如「留留留ge」）。这些是噪声：按上下文把意思理顺再写，不要把重复字、拼音原样搬进篇名或正文引语。
8. 篇名要像短篇小说的题目：二到八个汉字，干净，不要用噪声词。
9. 只输出正文，不分章。不要解释、不要 Markdown、不要代码块。

格式（严格遵守）：
第一行：篇名：<二到八个字>
第二行起：正文（段落之间空一行）
```

## 用户消息的拼法

```
这一天说过的话，按时间顺序：
1. <原话>
2. <原话>
...

这次的写法：
- 开头：<从一句没头没尾的原话开始 / 从一件器物发出的声音开始 / 从一个动作的中途开始 / 从谛听听见的第一个异常开始>
- 叙事手法：<欧·亨利式 / 海明威式 / 契诃夫式 / 鲁迅式>
- 素材 <去重后字数> 字（去重后），这一篇目标 <lo>–<hi> 字。

按规则把这一天写成一篇短篇小说。
```

被否认过的事件，原话后面会带「（这句被否认过，请换一种说法）」一并交给模型，和三栏的做法一致。

## 随机：每次换一种写法

`Lm.buildArticleBody()` 每次请求都从下面两组里各抽一条，写进用户消息：

- **开头**：一句没头没尾的原话 / 一件器物的声音 / 一个动作的中途 / 谛听听见的第一个异常。
- **叙事手法**：欧·亨利式结尾反转 / 海明威式冰山留白 / 契诃夫式日常暗流 / 鲁迅式冷峻白描。

底色固定是聊斋式志怪，抽到的只是这一篇的骨架。同一批原话点两次「重写」，读起来不会一模一样。

## 字数：按素材定，不按章数

代码先去重原话（`LinkedHashSet`，完全相同的句子只算一次），再按去重后的汉字数给区间：

| 去重后素材 | 目标字数 |
| --- | --- |
| < 600 字 | 700–1300 |
| 600–1500 | 900–1500 |
| 1500–3000 | 1200–2000 |
| 3000–6000 | 1800–2800 |
| > 6000 | 2500–3500 |

一天说的话多，篇就长；素材少，篇就短。模型只拿到区间，代码不硬切、不补写。

## 请求参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `model` | 默认 `deepseek-chat` | 跟三栏共用设置里的模型 |
| `temperature` | `1.0` | 要它敢写；太稳就写成日记 |
| `max_tokens` | `8000` | 三千五百字也够 |
| `stream` | `true`（阅读页）/ `false`（自动写） | 阅读页边收边按 80ms/字外放 |
| 读超时 | `300s` | 长文慢，别在中途掐断 |

接口与三栏相同：OpenAI 兼容的 `/chat/completions`，默认 `https://api.deepseek.com/chat/completions`。

## 输出怎么解析

`Store.Article.parse(raw)`：

1. 第一行认 `篇名：`（也兼容旧的 `书名：` / `标题：`），取作标题，缺省「听了一夜」。
2. 没有 `第N章` 时，整篇正文收成一个**无名章**；界面显示为「短篇 · N 字」，不画「第 一 章」。
3. 旧稿里如果有 `第N章`，仍然照旧切章、画章头，不丢字。

解析很宽容，因为模型偶尔不守格式；宽容的代价是排版可能不完美。

## 写坏的时候

非 2xx、超时、空正文、回包读不懂——都走 `Lm.fallbackArticle()`：把当天几句原话摆成一篇很短的志怪，每个字都发生过，只是不好看。阅读页底部会写「模型没连上，这篇是兜底写的」，自动写的通知也会标「（文章是兜底）」。

## 与三栏的关系

同一批原话，两种用法：三栏求**准**（JSON、短句、不确定就空着）；「写」求**像**（志怪、第一人称、可以写风声和灯影）。共同底线是同一条：只能用当天原话里出现过的事实，不许新增。
