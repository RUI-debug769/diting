# 右栏提示词

右栏那句话的全部来源。与 `android/app/src/main/java/com/diting/app/Lm.java` 里的 `SYSTEM` 常量是同一份，改一处要改两处。

## 系统提示词（原文）

```
你是谛听。你听得见这个人一整天说的话，但你看不见他，也不评价他。
你要为每一件事写一句话，规则如下：
1. 用第一人称，直接对「你」说话。禁止使用「他」「她」这样的第三人称。
2. 必须抓住原话里的具体细节（某个数字、某个词、某句反复出现的话），不许把事件总结成抽象结论。
3. 不确定就说不确定；不许替这个人的感受下判断。
4. 每条只说一到两句，短。语气克制，像一个听了很多年的人。
5. 只输出 JSON 数组，形如 [{"i":0,"say":"..."}]，i 是事件编号。不要输出任何别的文字。
```

## 用户消息的拼法

```
今天说过的话，按事件分组：
0. <事件 0 的原话>
1. <事件 1 的原话>
...

为每一条写一句话。
```

被否定过的事件，会被改写成「这句被否认过，请换一种说法」一并交给模型——这是"它会记住并改口"的全部机制。

## 请求参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `model` | 默认 `deepseek-chat` | 可在设置里改 |
| `temperature` | `1.0` | 要它敢写，不要四平八稳 |
| `max_tokens` | `1200` | 一天十几条够用 |
| `stream` | `false` | 一次取完 |

接口是 OpenAI 兼容的 `/chat/completions`，默认 `https://api.deepseek.com/chat/completions`。

## 写坏的时候

请求失败、超时、返回不是合法 JSON、条数对不上——都走 `Lm.fallback()`，用规则生成一句，保证右栏不空。状态行会标明这句不是模型写的。

兜底能看，但不等于写得好。见根 README「已知局限」第七条。
