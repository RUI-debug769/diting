# 记录格式

一天一个文件，一行一条 JSON，UTF-8，不带 BOM。五个字段都要有；`rewrite` 是唯一可以为 `null` 的。

示例见 [sample.jsonl](sample.jsonl)。

## 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ts` | string | 是 | 说这句话的本地时间，ISO 8601 带时区偏移，精确到秒，如 `2026-11-05T09:41:12+08:00` |
| `event` | string | 是 | 事件簇 id，形如 `<YYYY-MM-DD>-<两位序号>`，同一件事里的几句共用一个 id |
| `original` | string | 是 | 原话。识别出来什么样就存什么样：错字、断句、语气词，一个都不改 |
| `rewrite` | string \| null | 是 | 谛听写的那句；`null` 表示还没写 |
| `denied` | boolean | 是 | 用户有没有否定过。只标记，不删除这一条 |

### 事件簇

当前 App 的规则：同一天内，两句之间隔不超过 **90 秒**，算同一件事。阈值在 `MainActivity.EVENT_GAP_MS`，可以改。

### `rewrite` 的约束

它不是摘要，是理解。三条写死在提示词里（见 [`prompts/rewrite.md`](../prompts/rewrite.md)）：

1. 第一人称，直接对「你」说话，禁止第三人称。
2. 必须引到原话里的具体细节（某个数字、某个词、某句反复出现的话），不许总结成抽象结论。
3. 不确定就说不确定，不许替这个人下判断。

`null` 不等于空字符串：`null` 是"还没写"，空字符串是坏数据。

### `denied`

只标记，不删记录。原话永远保留——**改了就不是证据了**。

当前 App 的表现比较粗：被否定的那条，右栏直接换成占位话「（你说这不是我说的）」，原句不留；下一次重写时才把"这句被否认过，请换一种说法"交回去。这是已知局限第五条。

## 三条硬规矩

- **不存音频。** 任何字段里都不许出现音频路径、base64、二进制。
- **`original` 不做清洗。** 要修错字就另开字段，不要覆盖它。
- **导出、备份、迁移都以这个格式为准。** App 内部怎么存是另一回事。

## 例子

```json
{"ts":"2026-11-05T09:41:12+08:00","event":"2026-11-05-01","original":"今天那个会又拖到十二点，他们第三次讲同一页 PPT。","rewrite":"你把那场会记成了三次重复。你烦的不是拖堂，是他们讲的跟你记得的不一样。","denied":false}
{"ts":"2026-11-05T14:03:55+08:00","event":"2026-11-05-02","original":"这个方案我觉得不行，但是我说不上来哪儿不行。","rewrite":null,"denied":false}
{"ts":"2026-11-05T22:10:07+08:00","event":"2026-11-05-04","original":"算了，明天再说。","rewrite":"你说算了的时候，通常不是算了。","denied":true}
```

这三条是编的，不是谁的日记。
