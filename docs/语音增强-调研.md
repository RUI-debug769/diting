# 语音能力增强：候选清单与实测（2026-11-06）

> 结论先行：**今天真正能安全上线的只有一件——把 SenseVoice 的语种从写死 `zh` 改成 `auto`**。
> 认人（声纹）和多语种转写的更强模型都在社区里，但换它们要重录声纹或吃满内存，演示前不动。

## 1. 约束：这台机器有多大

| 项 | 实测 |
| --- | --- |
| CPU | 2 vCPU（Xeon Platinum 2.5GHz） |
| 内存 | 总 1736 MB，可用 878 MB |
| systemd 上限 | `MemoryMax=1200M` |
| 当前服务占用 | 284 MB（SenseVoice int8 + CAM++ + Silero VAD） |
| 磁盘 | 40 GB |

一句话：**任何新模型都得和另外 900MB 共用这 1.2G，而且只有两核。** 这排除了绝大多数"效果更好"的大模型。

## 2. 现状

| 环节 | 现在用什么 |
| --- | --- |
| 切句 | Silero VAD（sherpa-onnx 内置） |
| 认人 | 3D-Speaker CAM++ `zh-cn_16k-common`，192 维，28.3 MB，阈值 0.48 |
| 转写 | SenseVoice int8（中英日韩粤），`language` 之前写死 `zh` |

## 3. 实测：语种写成 auto 会怎样

同一份代码，只把 `language="zh"` 改成 `"auto"`：

| 样本 | 判定语种 | 转写 | RTF | 耗时 |
| --- | --- | --- | --- | --- |
| `zh.wav`（5.0s 中文） | `<\|zh\|>` | 开饭时间早上9点至下午5点。 | 0.130 | 0.65s |
| `en.wav`（英文） | `<\|en\|>` | The tribal chieftain called for the boy… | 0.181 | 0.81s |
| `ja.wav`（日语） | `<\|ja\|>` | うちの中学は弁当制で… | 0.121 | 0.49s |

- 中文文本与 `zh` 模式下**完全一致**，没有因为 auto 变差；
- RTF 都在 0.2 以下，2 核足够实时；
- 之前写死 `zh` 时，英文会被按中文音素强行解码——这就是"多语言不行"的真正原因。

## 4. 认人（声纹）候选

k2-fsa 的 speaker 模型 release 里，下面这些都能被 sherpa-onnx 直接加载，不用改推理代码：

| 模型 | 大小 | 说明 | 迁移成本 |
| --- | --- | --- | --- |
| `3dspeaker_campplus_zh-cn_16k-common`（现用） | 28.3 MB | 中文场景稳，英文偏弱 | — |
| `campplus_sv_zh_en_16k-common_advanced` | 28.3 MB | 中英双语版，**体积一样** | 低，但要重录声纹 |
| `eres2netv2_sv_zh-cn` | 71.4 MB | 中文 EER 更好 | 中，重录 + 多占 43MB |
| `eres2net_base_200k` | 39.6 MB | 多语种、通用 | 中 |
| `wespeaker_zh_cnceleb_resnet34_LM` | 26.5 MB | 中文电话场景 | 中 |
| `nemo_en_titanet_small` | 40.3 MB | 英文强、中文弱 | 只适合纯英文 |

**判断**：换声纹模型 = 已注册的 3 条模板全部失效（维度、分布都变），必须重新录。演示前一天做这个，风险大于收益。

真正低风险且有效的两个改动已经做了：
1. **短句加严**：`duration < 1.2s` 时阈值 +0.06。一秒内的句子向量不稳，同人常掉到 0.3 出头、异人也可能偶然冒高，加严比放宽安全。
2. **噪声事件过滤**（上一轮已上）：`<|BGM|>`/`<|Applause|>` 等不记账。

## 5. 转写候选

| 模型 | 语种 | 体积/算力 | 在我们机器上 |
| --- | --- | --- | --- |
| SenseVoice int8（现用，改 auto） | 中英日韩粤 | 小，RTF 0.13 | ✅ 今天已上 |
| Qwen3-ASR-0.6B int8 | 30+ 语种 + 中文 20 种方言 | 0.6B 参数，自回归解码 | ⚠️ 内存勉强、两核延迟风险大，**待实测** |
| Whisper small/medium（sherpa-onnx） | 99 语种 | small int8 约数百 MB，非自回归 | ⚠️ 中文标点/专名不如 SenseVoice |
| Paraformer-zh（sherpa-onnx） | 中文 | 小，流式 | 中文可换，但会丢掉日韩 |
| FireRedASR / Dolphin / FunASR-Nano | 中英为主 | 中等 | 值得之后 benchmark |
| Moonshine / Omnilingual ASR | 英/多语 | 小 | 英文场景可试 |

**Qwen3-ASR 是唯一"多语种 + 方言"都覆盖且已被 sherpa-onnx 官方支持的**，但它是 LLM 式解码器：每句话要逐 token 生成，2 核上很可能从 0.8 秒变成好几秒。**建议演示后单独测 RTF 再决定**，不要在演示前夜换。

## 6. 今天改了什么（已上线）

`cloud/diting_cloud.py`：

1. `Models.load`：`language="auto"`；
2. `Event` 增加 `lang` 字段，一行 JSON 里带上判定出的语种；
3. `Voiceprints.judge(embedding, extra=0.0)`，`need = min(0.99, threshold + extra)`；
4. `Pipeline.process`：`short = duration < 1.2` → `extra=0.06`；
5. `_asr` 记录 `result.lang`，事件里可见。

部署：`HOST=112.124.111.67 USER_=root bash cloud/deploy.sh`（密钥走 ssh config）。

## 7. 怎么复现

```bash
# 1) 直接看语种判定
ssh root@112.124.111.67 'cd /opt/diting && python3 - <<PY'
import sherpa_onnx, wave, numpy as np
r=sherpa_onnx.OfflineRecognizer.from_sense_voice(
    model="models/model.int8.onnx", tokens="models/tokens.txt",
    num_threads=1, use_itn=True, language="auto")
w=wave.open("/tmp/en.wav"); a=np.frombuffer(w.readframes(w.getnframes()),dtype=np.int16).astype(np.float32)/32768
s=r.create_stream(); s.accept_waveform(16000,a); r.decode_stream(s)
print(s.result.lang, s.result.text)
PY
```

## 8. 链路已验到哪一步

在服务器上单独起了一个 Pipeline（临时把阈值设成 -1，只为让它走进 ASR 分支，不影响线上服务）：

```
en.wav lang='en' accepted=True  text='The tribal chieftain called for the boy and presen…'
ja.wav lang='ja' accepted=True  text='うちの中学は弁当制で持っていきない場合は、50円の学校販売のパンを買う。'
zh.wav lang='zh' accepted=True  text='开饭时间早上9点至下午5点。'
```

也就是：**语种判定 → 转写 → 事件里的 `lang` 字段**这一段是通的。剩下只有一步需要人在场：

- **让主人在板子前说一句英文或日文**，确认 `lang` 从真实板子一路进到线上事件（这是唯一没验的环节）。

还没做的：
- Qwen3-ASR-0.6B 的实测 RTF（要先腾内存、装模型，演示后做）。
- 声纹模型的 A/B（要重录，演示后做）。
