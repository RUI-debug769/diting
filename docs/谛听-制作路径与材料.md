# 谛听 · 制作路径与材料

> 定稿：2026-11-05 13:00。主线已收敛为**一颗灯**。
> 已作废：带 480×320 屏的桌面件。`谛听-硬件-T5AI-实施路径.md`（272 行）保留作参考，其中 LVGL、屏刷新预算、五状态脸三节不再适用，只有采音与 TCP 帧格式那两节仍然有效。

---

## 0. 三层，各只做一件事

| 层 | 只做一件事 | 明确不做 |
|---|---|---|
| **硬件**：T5AI-CORE DevKit（73×29 mm，自带麦克风、喇叭、回声消除、锂电池管理） | 采音 → 推给手机；收手机状态 → 驱动一颗灯；被按一下 → 发一个事件 | 不做识别、不存数据、不画脸、不写日记、不连外网 |
| **手机**（安卓） | 收流 → 端点检测 → 本地识别 → 声纹只放行你 → 存文本 → **两栏界面** | 不做重写（那是夜里云端的事） |
| **云端** | 只收到文字，只做重写，输出带引用索引 | 永远不接触声音 |

数据流一条线：`麦克风 → 手机（本地转文字） → 云端（只重写） → 手机两栏`。

**脸不在硬件上。** 手机的屏就是谛听的脸。硬件身上只有一颗灯，五个状态。

## 1. 硬件端（T5AI-CORE DevKit）

### 1.1 今晚 40 分钟（P0，最高优先级）

目的不是做灯，是用最小代价把"这块板子能不能采音、能不能刷"问死。

| 时间 | 做什么 | 通过判据 |
|---|---|---|
| 0–10 min | 物理勘察：在 73×29 mm 板上找到 LED、咪头（Ø4–6 mm 金属壳）、喇叭、按键，拍照存档 | 确认灯是不是可控状态灯，不是电源指示灯 |
| 10–20 min | 编译基线：`source export.sh` → `tos.py` 新建一个最小 app，板选 `TUYA_T5AI_CORE` → `build` → `flash` | 串口能打出 `hello` 与版本号。**不过就停一切新功能** |
| 20–35 min | 采音探针：`tdl_audio_find("audio",&h)` → `tdl_audio_open(h, mic_cb)`，10 ms 一帧算 RMS，从串口打 | 安静 <200、说话 >1500、连跑 5 分钟不崩 |
| 35–40 min | 灯探针：`tdd_led_gpio` 控制 GPIO 9 亮灭三次 | 肉眼可见。若灯纹丝不动 → 走 1.3 的外挂方案 |

失败动作：
- `tdl_audio_find` 非 OK → 查 app config 里 `CONFIG_ENABLE_AUDIO_CODECS` 有没有被关掉。
- rms 恒 0 → 改 `cfg.ai_chn = TKL_AI_1` 再试 10 分钟，仍为 0 → 走降级（第 6 节第 1 条）。
- 只在敲桌子时跳 → 结构传声，加泡棉减震，接受"只做粗闸门"。

### 1.2 三条架构结论（现在就要接受）

1. **设备不做录音机。** 16K/16bit = 32 KB/s ≈ 115 MB/小时，PSRAM 差两个数量级。存储永远在手机，演示口径是 **5–10 分钟一场会话**。
2. **音频上行用手机热点 + TCP，不用 BLE。** 5 秒话 160 KB，TCP 不到 0.2 秒；BLE 实测 5–20 KB/s 要 8–16 秒，要先做 ADPCM 才能进 1–2 秒，那是把 60% 工时押在链路上。帧格式：`magic 0xA6 | type | len(2) | payload`，20 ms 一帧 640 B。
3. **声纹必须在手机侧。** 设备端没有现成的说话人识别推理栈。

### 1.3 那颗灯：单色，靠节律不靠颜色

**为什么不用七彩灯。** 七色 RGB 是消费电子的语言（音箱、路由器、扫地机都在用），一颗单色的灯在呼吸，才是生物的语言。而且单色省掉电平转换、省掉三根线、省掉调色调到崩溃的两小时。

板载 LED 在 GPIO 9、高电平点亮（`boards/T5AI/TUYA_T5AI_CORE/tuya_t5ai_core.c:26`）。`tdd_led_gpio` 只有开关、没有调光，所以呼吸要用定时器软件 PWM：20 ms 一步、256 级、占空比按正弦表走。CPU 代价可以忽略。

五态节律：

| 状态 | 节律 | 想让人看到什么 |
|---|---|---|
| 呼吸（待机） | 2.4 秒一轮，10% → 60% 亮度 | 它在，但没在忙 |
| 在听（有语音） | 0.9 秒一轮，亮度直接跟当前 RMS 走 | **它跟着你说话的音量起伏**——这是全场最抓人的一秒 |
| 听到别人 | 呼吸里插两次短跳（0.15 s 亮 / 0.15 s 灭 ×2），再回呼吸 | 它在分辨，不是在失灵 |
| 被否定 | 急闪三下，然后熄灭 1 秒 | 像被说了一句，闭嘴 |
| 夜间书写 | 5 秒一次极慢呼吸，写一句跳一下 | 睡着的时候它在写 |
| 断连 | 全灭 | 它不装还在 |

最后一条是白送的：评委拔掉手机时，你不尴尬，反而像"它在等"。

**外挂兜底（只在板载灯不可控时）**：WS2812B ×3 焊到 44 针排针的空闲脚，用仓库里的 `tdd_leds_pixel` 驱动（`src/peripherals/leds_pixel/`）。3 元、三根线、半小时。但拿到 WS2812 也别用七彩——只用亮度通道做上面那张表。

### 1.4 外壳

- 目标外形：一个 80×45×22 mm 的鹅卵石，一个孔给咪头，一个孔给喇叭，一颗灯从磨砂壁透出来。
- 材料：PLA 打印（主办方有拓竹，但文档说设备在"西湖文三路授权专营店"，是否现场待确认）→ 若现场没有，用现成深色塑料小盒 + 挖孔 + 桌垫磨砂片。
- 不做：卡扣、螺纹、磁吸。热熔胶就是正确工艺。
- 设计师甲交的是 STL 与三张剪影，不是渲染图。

## 2. 手机端（安卓）

七步，每步一句"关键 API + 最大的坑"：

1. **录制前台服务** — `Foreground Service` + 常驻通知，持有 `ServerSocket` 收设备推来的 16K/16bit 单声道流。坑：Android 14 必须声明 `foregroundServiceType`（连设备用 `connectedDevice`）；国产 ROM 会锁屏杀进程，要加电池白名单。
2. **端点检测** — sherpa-onnx 自带 Silero VAD 在手机侧精筛，设备端只做能量粗闸。坑：固定阈值在会场噪声与方言拖音下会把一句话切碎，必须留 300 ms 前后缓冲并现场标定。
3. **本地识别** — sherpa-onnx + SenseVoice int8 中文（arm64-v8a）。坑：模型文件名与接口随版本变化、首次加载体积不可控、方言词必然错字。**这一步最可能吃掉一天。** 对策：先跑 30 分钟"一句话识别"spike，不通立刻切系统 `SpeechRecognizer`，再不通切笔记本局域网兜底，叙事不变。
4. **手机侧声纹** — sherpa-onnx 说话人嵌入（3D-Speaker CAM++ 类），注册录 3 段各 5 秒取平均嵌入，运行时算余弦相似度。坑：阈值只能现场调；嘈杂会场"误接"比"误拒"更毁演示。
5. **Room 存储** — 只落文本与元数据，音频处理后即弃、只留 30 秒环形缓冲。坑：别把音频当 BLOB 入库；开 WAL、单写者。
6. **夜间云端重试** — `WorkManager`（充电 + 联网约束）+ 指数退避，按日期幂等去重。坑：Doze 与国产 ROM 会让 Worker 夜里根本不跑；演示前手动触发一次并缓存，失败降级本机模板重写。
7. **两栏界面** — Compose 双栏 + 按句索引对齐。左栏零改写原话，右栏谛听重写，**逐句映射**。点"这不是我说的"要写回教学词条、触发局部重写、并给硬件发 `EV_DENIED`。**这张屏就是它的脸**，所以它同时是交互界面和角色呈现。

## 3. 云端叙事层

| 步骤 | 做法 |
|---|---|
| **聚类** | 每句带时间戳、说话人、声纹标记、否认标记。先按 25 分钟静默与声纹切换切段，再按句向量相似度贪心合并成簇；簇数 >30 抬阈值、<15 拆最长簇；每簇只留摘要与原句索引。 |
| **重写骨架** | 人设四句：我是谛听、嘴硬记性差、会替你美化丑事、记不住语气只记名词。硬规则：每段必引一个原话里的具体名词、禁止说教、**允许记错一处时间地点**、输出带引用索引与置信度。 |
| **否认负样本** | 点"不是他说的"即写进否决表（句哈希 + 时间）；重写时从引用池剔除、作为反例列在提示词末尾、同话题其他句降权；同类否决满三条生成一条风格禁令。 |
| **方言层** | 手机保留方言原文，云端只做**词级受控翻译**：词表命中直接替换，未命中标成问号词回传让用户教。日记只用普通话文本 + 原始方言词引用，**不让模型自由意译**。 |
| **词表结构** | 一词一条：方言写法、读音、普通话对应、一句人话解释、原话例句、教的人、地区、置信度、教学时间、使用次数。命中即用，连对三次升稳定词，可撤回可导出。 |

三条自查：随机三天重跑聚类，事件数落在 15–30；每段至少一个名词能在原话里按索引找到；被否决句复现率为零、误伤率 <5%。

## 6. 三条降级路径

1. **板子采音或刷机失败** → 手机当麦克风（前台服务直接录），板子退成一颗会呼吸的灯。叙事从"它在你身上听"变成"它在你手机里记，在你桌上呼吸"，硬件仍入镜、仍可交互。
2. **方言识别不准**（<70%）→ 脚本只锁一个方言关键词，其余用普通话；"教它一个词"单独演。这一条不影响文化表达分，因为观众看的是"它问你、你教它、它记住"。
3. **云端不通或延迟 >3 秒** → 预生成一份成品日记兜底，现场只做一次真实调用；失败降级本机模板。

## 8. 还没解的问题

1. **板载 LED 是不是可控状态灯**（GPIO 9，高电平亮）——今晚 10 分钟肉眼确认。若只是电源灯，转 WS2812。
2. 手机型号与 Android 版本：影响热点网关 IP（192.168.43.1 还是 192.168.232.1）与"开热点能否同时上蜂窝网"。
3. 拓竹 3D 打印机是否真在白马湖现场（文档写"西湖文三路授权专营店"），决定外壳走打印还是手工。
4. `tos.py` 新建 app 时板级选择 `TUYA_T5AI_CORE` 能否直接出包——CORE 板没有屏，`apps/shardcard` 那套 LVGL 配置不能直接复用。
