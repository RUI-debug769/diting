# 云端声纹链路（板子 → 云 → App）

> 一句话：挂坠把 PCM 推上云，云切句、认人、转字，只把「主人说的话」推到 App 左栏。
> 认人用 3D-Speaker 的 CAM++（ONNX，192 维），转字用 SenseVoice-small（ONNX，int8），
> 两者都跑在 sherpa-onnx 上，没有 torch、没有数据库。

## 分工

```
挂坠 T5AI ──TCP:19001──▶ 云 ──TCP:19002──▶ App
   PCM16k/16bit/单声道        只推 accepted=true 的句子
                                 ▲
   App ──TCP:19003 注册我的声音──┘
```

| 端口 | 谁连 | 内容 |
| --- | --- | --- |
| 19001 | 挂坠 | 4 字节小端长度 + PCM 帧（与 `NetRx.java` 同格式，`len<=0 \|\| len>8192` 丢弃） |
| 19002 | App | 一行一个 JSON：`{"type":"utterance","speaker":"me","score":1.0,"text":"…","accepted":true}` |
| 19003 | App | 同上帧格式推一段语音，推完关连接；云回一行 `{"ok":true,"kind":"enrolled",…}` |

三个端口的帧格式是同一个，所以 `tools/sim_board.py` 和 `tools/enroll_push.py` 都能直接对着云跑。

## 云上做了什么

1. **切句**（Silero VAD）：`ai_audio_input` 送上来的是连续流，按 `min_silence_duration` 断开；
   短于 0.25s 的段当噪声丢掉。
2. **认人**（CAM++）：切出来的每一段算 192 维向量，和 `data/voiceprints.json` 里的主人向量算余弦。
   阈值 `--threshold`，默认 **0.62**。低于阈值 → `speaker=other`，`accepted=false`，**不转文字**。
3. **转字**（SenseVoice int8 + ITN）：只有 `accepted=true` 才解码，省 CPU（这台 ECS 只有 2 核 1.7G）。
4. **推给 App**：`Hub` 里挂着所有 App 连接，逐行写 JSON。

声纹只存一条「主人」向量，没有用户表——产品上就只有一个「我」。

## 部署（阿里云 ECS <你的服务器>）

```bash
cd cloud && ./deploy.sh          # rsync 代码 + scp 模型 + systemd 起服务
```

- 服务：`/etc/systemd/system/diting.service`，`MemoryMax=1200M`，日志 `/var/log/diting.log`
- 代码 `/opt/diting`，模型 `/opt/diting/models`，声纹 `/opt/diting/data/voiceprints.json`
- 这台机器**没有 python3-venv**，`deploy.sh` 直接用系统 `python3 + pip3`
- 重启必须 `systemctl restart diting`——`enable --now` 不会重启已经在跑的服务

## App 侧

- `Cloud.java`：长连接 19002，断线 3 秒重连，JSON 回主线程 → 和手打「说一句」走同一条 `addSpoken`
- `Enroll.java`：`AudioRecord` 16k/单声道/16bit 录 8 秒，按 4 字节小端长度推给 19003
- 设置里（长按日期）可以改云端地址、端口，注册口固定是「云端端口 + 1」

## 注册的规矩

第一次录：直接存。
之后再录：先和已有向量比，**相似度 < 0.5 就不覆盖**，回 `kind=mismatch`。
这样路过的人对着手机说一句，换不掉你的声纹。

## 只在你选的时段里记（2026-11-05 加）

板子永远在推，**「记不记」由云端判**——这样改时段不用重烧固件。

- 存 `data/window.json`：`{"start":"09:00","end":"10:00"}`。
- `start == end` 表示**全天**；`start > end` 表示**跨零点**（`22:00`→`07:00` 就是今晚十点到明早七点）。
- 不在时段内：`_drain()` 先把 VAD 里积的段 `pop()` 掉再继续，**不跑声纹也不跑识别**，一点东西都不留。
- 状态变化才打日志：`记录时段 09:00-10:00：到点了，先不记` / `开始了，只记这段`。

设置页改时段走的是**已经在放行的 19002**，不新增端口：连上去写一行 JSON，读一行回来。

| 命令 | 回什么 |
| --- | --- |
| `{"cmd":"status"}` | `{"type":"status","enrolled":true,"window":{"start","end"},"in_window":true,"threshold":0.62}` |
| `{"cmd":"window","start":"22:00","end":"07:00"}` | 同上（写完盘再回） |
| `{"cmd":"wipe"}` | 同上，`enrolled` 变 `false` |

这条口同时在广播 utterance，所以 App 端读答复时要把 `type=utterance` 的行跳过去（`Control.java`）。

实测（2026-11-05 17:54）：

17:54:42 记录时段 09:00-10:00：到点了，先不记     ← 这段音频被丢掉，没有 事件 行
17:55:08 App 把记录时段改成 00:00-00:00
17:55:23 记录时段 00:00-00:00：开始了，只记这段
17:55:24 事件 {"speaker":"unregistered","text":"开饭时间早上9点至下午5点。","accepted":false}

## 录声纹：录不到 1.5 秒时不再硬来

真机上连试四次都是 `speech_seconds: 0.83`——VAD 只从 8 秒里挑出不到 1 秒，
多半是手机麦克风小、人离得远。拿 0.8 秒去定一个人的声音太冒险，现在的兜底是：
**VAD 挑出的语音不足 1.5 秒，就改取整段里能量最高的 3 秒**（`_loudest_window`，20ms 一格的 RMS 滑窗）。

删声纹：`Voiceprints.wipe()` → 清空向量并写盘，之后谁说话都是 `unregistered`，重新录一次才算数。

## 2026-11-05 19:12 新增：用板子自己的麦克风录声纹 + 多模板

手机录的声纹判板子的声音，分数总在 0.6 上下摇摆（阈值 0.62），一会儿认一会儿不认。原因是**录音链路不同**：手机录是手机麦克风，判断时用的是板子麦克风，信道一换 CAM++ 的分数就往下掉。

- 新增控制命令 `{"cmd":"enroll_board"}`：云端在 30 秒内把**板子**切出来的第一段话直接存成声纹，录完往 App 广播 `{"type":"notice","text":"用板子记住了你的声音"}`。App 的入口在 设置 → 「用板子的麦克风录（对着板子说 8 秒）」。
- 声纹存储改成「**最多 3 条模板，取最高分**」：`voiceprints.json` 的 `speakers.me` 从 `[192 个数]` 变成 `[[…],[…]]`，旧格式仍可读；新录的如果和已有模板相似度 ≥0.92 就替换那一条，否则追加，超过 3 条丢最旧的。
- 判定仍用 0.62 阈值，实测同人 0.68–0.73、陌生人 0.0–0.2，分得开。
- 短于 **1 秒**的片段直接当噪声（之前 0.6 秒的碎片会判成 `other`，App 上刷一排「不是你的声音」）。VAD `min_silence_duration` 0.45 → 0.75，`threshold` 0.5 → 0.42。
